# 首页麋鹿的奔跑素材

首页的奔跑动画不直接播放生成插画，而是用这里的脚本离线烘焙成 50 帧灰度图。这个目录不进网站构建。

```text
source/milu-cycle-*.png   内置 imagegen 生成的七张彩色透明图集（gather 只作参考，不参与烘焙）
drawings.json             选用的 31 个完整姿态：顺序、所在图集与格子、躯干原点、比例、停留时长
bake.py                   烘焙脚本
heads.json                最近一次烘焙的头部测量：原位置、目标位置、角度和大小
requirements.txt          脚本依赖（固定版本）
```

## 重新烘焙

```bash
python3 -m venv .venv && .venv/bin/pip install -r art/milu/requirements.txt
.venv/bin/python art/milu/bake.py --preview /tmp/milu-sheet.png
```

脚本会覆盖 `apps/website/assets/milu-run-*.png` 和 `apps/website/scripts/meadow/stride.js`。同一版本的依赖下，输出逐字节一致。改完后运行 `npm test`，再看首页。

## 烘焙做了什么

这些姿态是分别生成的，头的大小、角度和鹿角形状每张都略有不同，毛色也有差别。以前在页面上对相邻两张整帧溶解，交接时会同时出现两个头、两组腿。脚本依次做这几件事：

1. **对齐**：按躯干原点和地面线把每张图放到同一坐标和比例里，丢掉透明度低于 8 的生成底雾。
2. **头部**：以 `headReference` 那张为参照，测出每张图的头部位置、角度和大小。保留步态里头部本来的起伏（每步两次），用低阶傅里叶曲线滤掉逐张的抖动，并统一大小。每张图用的仍是自己的头，只沿颈部平滑地移到目标位置，躯干和四肢不动。鹿角按头部刚性对齐到参照鹿角。
3. **色调**：把每张图的鹿身灰度对齐到同一水平，避免网点阈值附近闪动。
4. **中间帧**：在相邻姿态之间用 Farneback 光流双向变形，生成真正的中间姿态。光流窗口取 51px，让快速转动的腿整条一起移动；窗口小时腿会在推蹬和收腿处被撕成几截。两张图里都踩在地上的蹄子，中间帧里锁住竖直方向，只沿地面滑动。光流对不齐的地方只取较近一侧的那条腿，并清掉离实心轮廓过远的拖尾和挂在淡边上的散毛，不出现两条半透明的腿。
5. **输出**：按步态均匀取 50 帧，正好是奔跑速度下每次 60Hz 刷新一帧。套用网站的灰度曲线和细轮廓，缩到每场景单位 120px，打包成两张灰度透明图集，并生成描述帧位置的 `stride.js`。

页面运行时只取帧：奔跑时每次刷新显示一整帧；跳跃空中步态变慢时，才按速度在相邻帧之间淡入淡出。

## 调整

- 换姿态、改顺序或节奏：编辑 `drawings.json` 的 `drawings`（`duration` 是相对停留时长），再烘焙。
- push 图集里的源编号 38 没有使用：画中远侧后蹄在髋下就离地，再到空中往后甩，接在 37 和 39 之间会让后腿蹬地看起来像空中踢腿。去掉后由 37 直接过渡到 39，远侧后腿边向后推边离地。
- `frames`：每个步态周期的帧数。网站按 1.2 步/秒奔跑，50 帧对应 60fps；改帧数要同时改 `cycle.js` 的 `GALLOP_RATE`，否则奔跑会在相邻帧之间混合。
- 跳跃用到的姿态在 `cycle.js` 的 `JUMP_KEYS` 里按源编号引用，增删姿态时要一起检查。

## 已知限制

- 后腿从“向后伸直”到“向前收起”（源编号 24 → 25 → 10）和蹬离地面（40 → 41 → 8）在原图之间跨度很大，每帧腿移动的距离约是其他时段的两倍。中间帧现在是完整的单条腿，但动作仍然很快；要更舒展，需要补画中间姿态，或者从别的时段挪出时间。
- 前腿支撑阶段，原图中着地前蹄相对地面有约 0.1 个场景单位的前后滑动，烘焙没有修正。
- 不同图集的鹿角分叉细节仍有细小差异，只能对齐整体位置和大小；毛发纹理在中间帧里是两张原图的过渡。
- 这组原图画的是成对着地、长时间腾空的蹦跳，和真鹿的奔跑不同，见 [真鹿奔跑参考与差距](../../reviews/reference/milu-real-gallop.md)。按真鹿重画试过一次，效果不被接受，已撤回，见 [按真鹿重画](../../reviews/reference/milu-real-gallop-redraw.md)。
