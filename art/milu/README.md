# 首页麋鹿的散步素材

首页保持散步和原来的鹿形。4 个关键姿态提供蹄子轨迹，躯干和近侧两条腿使用一张连续皮肤，远侧腿从后方遮挡。一个完整左右步循环含 160 帧，每秒 0.75 个循环，素材按 120 帧/秒采样，网页以 60fps 为目标绘制。160 帧是离线姿态采样，不是独立生成的插画。

```text
source/milu-walk.png      imagegen 生成的 4×2 原始散步图集，保留不改
source/milu-cycle-*.png   旧奔跑参考，不参与当前烘焙
drawings.json            选帧、注册位置、比例、步频、采样数和停下姿态
register.py              从散步原图测量注册位置
landmarks.json           四条腿的关节与蹄子中心线，绑定原图和注册数据
limbs.py                 连续蹄子轨迹、解剖关节、后腿长度约束与前后遮挡
skin.py                  躯干与近侧腿共用的连续表面，单次纹理采样
body.py                  头、颈、躯干的统一运动与腿根连接
bake.py                  对齐、补间、灰度处理和图集打包
motion.py                整帧横向偏移与可见蹄子接地时刻的测量
heads.json               旧版独立头部处理的历史报告，当前流程不再读写
requirements.txt         固定版本的离线依赖
test_bake.py             离线动作回归测试
upper-body-lock.json     历史版本整个上半身的逐帧像素指纹
motion-core-lock.json    本次修改前头颈、躯干核心与尾巴的逐帧像素指纹
test_body.py             统一运动与上半身像素保护回归测试
```

## 重新烘焙与验证

```bash
python3 -m venv .venv
.venv/bin/pip install -r art/milu/requirements.txt
.venv/bin/python art/milu/bake.py --preview /tmp/milu-sheet.png
.venv/bin/python -m unittest discover -s art/milu
npm test
npm run dev
```

烘焙覆盖 `apps/website/assets/milu-run-*.png` 和 `apps/website/scripts/meadow/stride.js`。目录本身不进入网站构建。浏览器只加载两张成品灰度图集，不运行光流或网格计算。

需要重新测量注册位置时：

```bash
.venv/bin/python art/milu/register.py source/milu-walk.png --cells 1 6 3 8 > art/milu/drawings.json
```

原图、选帧、注册位置或比例改变后，必须相应重新标注 `landmarks.json`。烘焙会核对原图哈希与注册数据，避免把旧关节坐标套到新图片上。

## 为什么原来 60 帧仍然顿挫

旧补间遇到对不齐的腿，会用 `t >= 0.5` 在两张图之间直接换腿。细腿的大幅旋转无法靠相似的毛色可靠匹配，因此这条分支会在抬脚、落脚时造成位置突变。另外，每帧按透明度重新删除小碎片，会让较细的蹄子忽隐忽现；运行时整帧取整也会放大刷新时间的微小偏差。

当前处理顺序：

1. 对齐完整原图并匹配灰度，源图碎片只清理一次。`bodyReference` 选定同一张头、颈、躯干连在一起的上半身，不再对头或鹿角单独拟合。
2. 单调三次曲线连接已测量的蹄子轨迹，位置和速度连续、着地高度不超调。肩、髋使用固定的真实连接点；后腿原来的第一个标记实际是膝关节，不能把后面的胫骨中点当成另一个关节。校正后约束三段骨长，跗关节始终向同一侧弯曲；蹄子保持原形状和落点，接近地面时平稳放平。
3. `skin.py` 将躯干、近侧后腿和近侧前腿绑定到同一张连续表面，连接边共用顶点和纹理坐标。肩、髋附近允许随迈步变形，头颈和躯干核心由稳定锚点保护。约束三角剖分保留凹形边界，明确的腿部条带防止跨空隙拉伸纹理。
4. 近侧表面只采样一次，不再把分别淡出的身体与腿片叠加；远侧腿保留完整的上端，从身体后方遮挡。源图邻腿碎片只清理一次，最终透明边缘在身体运动之后统一处理。
5. `body.py` 为头、颈、躯干施加同一个小幅起伏和俯仰，周期直接取自步态。共同变换向腿根延续，在蹄子附近衰减为零，保持着地。移除原来的水平切线及固定上身回贴，避免将已转动的上腿再次截断。
6. 完整左右步均匀采样 160 帧，两个半步始终保留四条腿的身份与遮挡顺序。网页按真实时间在线性相邻样本间取值，保持原来的步频；点击只触发上色，不再改变动作。

`landmarks.json` 使用 `bake.py` 的工作坐标：680×540，躯干原点/地面为 `[290,470]`，每场景单位 180px。每条腿保留 5 个原始测量点；`roots` 存储重新校准的肩、髋连接点，读取时纠正后腿关节的语义。它是现有插画的对应信息，不是新的鹿造型。

## 验收与限制

`stride.js` 的 `bodyMotion` 记录统一运动参数。此类素材的 `offsetX` 为零，避免再次按躯干平移，把设计好的整体运动抵消。`motion.py` 继续测量胸腹部位置与蹄子接地时刻；运行 `python art/milu/motion.py --update` 会保留统一运动。没有 `bodyMotion` 的历史图集才使用整帧横向注册。

`footfalls` 从修正后的蹄子接地位置测量。雪地和沙地只在越过接地时刻时产生少量贴地颗粒，颗粒跟随地面滚动，约 0.3 秒内消散；停下时不持续产生。草地、森林和夜景不再附带蹄子烟团或星形喷射。接地颗粒逻辑见 `apps/website/scripts/meadow/footsteps.js`。

离线测试覆盖循环首尾位置与速度、蹄子高度不超调、固定骨长、640 个时刻的表面不翻折，以及接缝无透明孔洞和重复叠加。`test_body.py` 追踪实际输出的头、颈、躯干像素：必须共同起伏，距离保持不变；蹄子区域像素不被身体运动移动。`motion-core-lock.json` 在本次修改前生成，保护全部 160 帧中的头颈、躯干核心和尾巴；肩、髋及下腹属于必要的变形区域，不纳入原来的整块上半身锁定。Node 测试检查实际时间采样、60fps 调度、点击上色不改变步态、地面边界和图集加载。测试通过不能替代正常速度的视觉验收。

- 蹄子轨迹仍来自四张关键姿态，后半步由相对侧的路径延续；没有重新生成原图。
- 这是侧面二维动作，腿部皮肤由同一参考重用，尚未模拟关节在深度方向的旋转。上半身继续使用已确认的统一运动，目前不包含耳朵等次级动作。
- 地面速度从着地蹄子轨迹估算，不代表每一只蹄子在所有帧里都完全无滑动。
- 两张图集合计约 4MB，尺寸为 2256×2710；较半步循环增加约一倍素材。浏览器的绘制方式和 60fps 目标不变，未实测所有设备帧耗时。
