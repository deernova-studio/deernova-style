# 60 张走路姿态：原图直连

按用户要求重新生成 60 个姿态。使用内置 image_gen，共六张图集，每张 5 列 × 2 行，对应连续 10 帧；裁切得到编号 001–060 的 PNG。没有调用图片生成 CLI/API。

## 输出

- `frames/frame-001.png` 至 `frames/frame-060.png`：60 张单帧图，统一为 416×416 白底画布。
- `sheets/`：六张原始生成图集，完整保留。
- `walk-60fps.mp4`：按 001→060 直接逐张播放，60fps，每轮 1 秒，共 6 轮。
- `walk-half-speed.mp4`：相同 60 张原图以 30fps 播放，每轮 2 秒，共 3 轮；便于看落脚和接缝。
- `walk-60-frames.zip`：60 张 PNG 和来源清单。
- `contact-sheet.jpg`：按时间顺序排列的全部 60 帧。
- `manifest.json`：每帧所属图集、裁切位置、SHA-256 和播放参数。

## 生成与拼接

`prompt-*.txt` 保存六组完整提示词。角色画风参考 `art/milu/source/milu-walk.png`，各组也参考相邻组或开头组保持造型与衔接。`blocking.json` 是提示词中的预设脚位和支撑阶段，不是对生成结果的实测，也不代表生成模型逐点执行了这些约束。

`assemble.py` 只按固定网格裁切、在同一图集中使用统一比例缩放并居中到固定画布，然后顺序编码。没有光流、RIFE、交叉淡化、网格变形、独立头部固定或用插值合成额外姿态。正常速度的视频每一帧都有对应的原始 PNG。

重新拼接（需要 Pillow 和 FFmpeg）：

```sh
python assemble.py
```

此目录仅提供动作图和直连视频，没有替换首页，也未提交 Git。60 张生成图与 60fps 输出是数量和播放方式，不等于步态已通过视觉验收。

## 实际检查结果

60 张 PNG 文件哈希互不相同，六张原始图集和六份完整提示词均已保存。ZIP 完整性检查通过，包含全部 60 张 PNG。原速视频为 960×720、60fps、360 帧、6 秒；原速和半速视频都已完整解码，无文件损坏。

视觉检查未通过自然步态验收。第 30→31、40→41 帧仍有明显姿态跳变，10→11 和 50→51 帧也有落脚位置/关节弯曲差异；分组生成没有严格遵守连续脚位。另有体形与毛色细节变化。这些问题保留在原图直连结果中，没有用补间或变形掩盖。相邻组的前后两帧见 [接缝检查图](seam-review.jpg)。
