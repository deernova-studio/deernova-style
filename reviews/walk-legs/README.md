# 腿部交叠与后腿连续性 · 2026-11-04

## 问题与修改

旧版先把腿合成，再做整体光流。交叠时容易把相邻腿的皮肤混到一起，产生透明重影、轮廓拉扯；宽度固定的变形网格在后腿折起时也会折叠覆盖。原半步循环还会在首尾交换左右腿身份，造成遮挡顺序变化。

本次从无遮挡的参考姿态提取完整腿部皮肤，分别变形四条腿。透明网格边缘不再覆盖已有的皮肤，前腿与后腿都使用明确的远近遮挡，不对交叠后的整张图做光流。

后腿两段采用固定长度，通过关节弯曲跟随原蹄子轨迹；蹄子保持原比例，接近落地时平稳放平，着地后不再绕脚尖晃动。源模板中混入的邻腿碎片只清理一次，不按播放帧重新删除碎片。

循环从半步 80 帧改为完整左右步 160 帧，每秒 0.75 个完整循环。四条腿保持各自身份与遮挡次序，两侧都走完一步后再回到开头。步频、每秒 120 个素材采样和网页 60fps 绘制目标不变。

## 上半身保护

`bodyMotion` 的参数和节奏保留。新腿部直接连接身体，不再额外做腿根光流。头颈、鹿角和躯干核心区域在相同播放时刻逐像素比较：**160 / 160 帧完全一致，最大差值 0**。

基准来自本轮修改前的图集，记录在 `art/milu/upper-body-lock.json`。`test_body.py` 会对打包后的实际图片进行核对，不仅检查运动函数。

## 验证与限制

- `npm test`：55 项通过。
- `python -m unittest discover -s art/milu`：10 项通过。覆盖关节路径连续、后腿长度与蹄子比例、着地蹄子方向、遮挡不透明、完整循环像素一致，以及上半身逐帧保护。
- 首页开发服务已加载新图集。两张图片仍使用原文件名，单张尺寸 2256×2710，总量约 4MB；`git diff --check` 通过。
- 这是基于四个原始姿态的侧面二维动作，尚未模拟深度方向的关节旋转。源图落点节奏仍会影响局部滑动；测试通过不代替实际观看，也未实测所有设备的浏览器帧耗时。
