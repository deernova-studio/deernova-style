# 反馈与通知

用户做了一件事、系统发生了一件事、某个地方出了错，该用哪种方式告诉用户。原则是**离事情发生的地方越近越好，打断越少越好**：能在原位显示的不弹出来，能自动消失的不让用户去关，能撤销的不先问。

## 先选对方式

从上往下找第一条符合的：

| 情况 | 用 | 例子 | 见 |
| --- | --- | --- | --- |
| 操作成功，界面本身已经变了 | 不提示 | 勾选任务、切换开关、重命名 | — |
| 操作成功，但结果在屏幕上看不到 | 轻提示（2 秒） | 已复制、已保存到相册、已发送邀请 | [横幅与轻提示](../components/banner.md) |
| 删除、归档、移动这类可以撤销的操作 | 直接做，轻提示带「撤销」（6 秒） | 已删除 3 条笔记 · 撤销 | 同上 |
| 不能撤销的破坏性操作 | 先确认：弹窗；AI 里是确认卡 | 永久删除、清空回收站 | [弹窗](../components/sheet.md)、[确认与审批](../components/approval.md) |
| 某个字段填错 | 字段下方的错误文字 | 邮箱格式不对 | [表单](../components/form.md) |
| 一块区域加载或保存失败 | 原位置换成原因加「重试」 | 评论没有加载出来 | [加载状态](../components/skeleton.md) |
| 后台操作失败，屏幕上没有它的位置 | 错误轻提示，不自动消失 | 移动失败：没有目标文件夹的权限 | [横幅与轻提示](../components/banner.md) |
| 影响整个页面、需要知道的状态 | 横幅 | 只读模式、额度快用完、新版本已就绪 | 同上 |
| 影响整个应用的连接状态 | 全局状态条 | 网络已断开、正在重新连接 | 下面的[全局状态](#全局状态) |
| 用户不在看的时候，后台的事完成、出错或需要他 | 通知（应用内标记，必要时系统通知） | 任务已完成、等待你确认、有人提到你 | [通知](../components/notification.md) |
| 整个页面打不开 | 错误页 | 找不到页面、没有权限、服务出错 | [空状态与错误页](../components/empty-state.md) |
| AI 运行中的某一步失败 | 步骤上的失败图标，回答里说明，原位「重试」 | 命令退出码 1 | [AI 交互](ai.md) |

## 规则

- **一次一个**：同时最多一个轻提示、一个弹窗、一条页面横幅。新的轻提示直接替换旧的；页面上有几件事都要用横幅说时，只留最重要的一条。断网、新版本这类[全局状态](#全局状态)不算页面横幅，可以和一条页面横幅同时出现。
- **成功会消失，错误会留下**：确认类的提示自动消失；错误一直在，直到问题解决或用户关掉。
- **严重程度只用于错误和警告**：成功用 `success` 图标，警告 `warning`，错误 `danger`，其余（信息、进度）都是中性的 `ink-secondary`。颜色永远配一句文字，不单靠颜色。
- **不抢焦点**：除了确认弹窗，所有提示出现时焦点都留在原处；用户正在输入时不打断。
- **能撤销就不问**：可以撤销的操作不弹「确定要删除吗？」，做完给撤销。
- **保住用户的东西**：出错时用户填的、写的内容原样留着；重试不需要重新填。
- **只提示一次**：同一个错误反复发生（例如每 5 秒重试失败）时不反复弹出，原来那条更新文字或计数。

## 时长

| 方式 | 停留 | 说明 |
| --- | --- | --- |
| 确认类轻提示 | 2 秒 | 没有按钮 |
| 带撤销或动作的轻提示 | 6 秒 | 鼠标悬停、键盘焦点在上面时暂停计时 |
| 错误轻提示 | 不自动消失 | 带关闭按钮，可以有「重试」 |
| 横幅 | 直到状态结束或用户关闭 | 状态结束时自动收起 |
| 全局状态条 | 直到恢复 | 恢复后换成「已重新连接」轻提示 |
| 通知 | 留在通知中心，直到已读 | 系统通知由系统决定停留时间 |

## 错误怎么写

- **三句话以内**：出了什么事 → 原因（知道的话）→ 用户能做什么。「移动失败。你没有『设计稿』文件夹的编辑权限，可以请所有者添加你。」
- **标题说事实，不说「出错了」「操作失败」**：写清是哪件事失败了。
- **按钮写动作**：「重试」「请求权限」「复制错误详情」，不写「确定」「知道了」。
- **错误码放在最后**：错误编号、请求 ID 用 `caption`、`ink-tertiary`、等宽，放在正文后面或「详情」里，可以复制；不放在标题里。
- **不责怪用户，也不道歉**：不写「你输入的内容有误」「非常抱歉」；写「这个邮箱已经注册过了」。
- **不露技术细节**：堆栈、内部错误名、HTTP 状态描述不给普通用户看。
- 更多写法见 [文案](writing.md)。

## 全局状态

影响整个应用、但不妨碍继续使用的状态，放在固定的位置：

- **位置**：Web 应用和 macOS 放在内容区顶部（顶栏下方），对话类页面放在 Composer 正上方，样式用中性横幅，宽度和内容一致；iOS 放在导航栏下方。
- **网络断开**：「网络已断开 · 修改会在恢复后同步」，中性横幅，图标 `ink-secondary`；不能保存的情况才用 `warning`。
- **正在重新连接**：同一条横幅，图标换成 `spinner` 动效，文字「正在重新连接…」。
- **恢复**：横幅收起，如果断开超过 5 秒，补一个轻提示「已重新连接」；很短的断开不提示。
- **新版本**：中性横幅「新版本已就绪」加「重新打开」，可以关闭，关闭后这个版本不再提示。
- 全局状态最多一条（断网优先于新版本）。它和一条页面横幅同时存在时，全局状态在上，页面横幅在下；最多这两条。

## 无障碍

- 确认、进度和中性提示用 `role="status"`（礼貌朗读）；错误轻提示和危险横幅用 `role="alert"`（立即朗读）。
- 轻提示里的动作在别处也能做到（撤销对应 ⌘Z / Ctrl+Z，重试在原位也有），因为它会消失，不能是唯一入口。
- 自动消失的提示在鼠标悬停和键盘焦点在上面时暂停；开启「减弱动态效果」时只淡入淡出，不移动。
