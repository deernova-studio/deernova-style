# 文案

## 少写字

界面靠标题、布局和图标说话。用户不读界面上的字，只扫：扫到标题就知道这是什么，扫到按钮就知道能做什么。每多一行小字，要扫的东西就多一行，真正要紧的那句就更难看到。

这一节管界面上的字（标题、标签、说明、提示、徽标），不管 AI 回答、文章和用户自己的内容。

### 先删再写

1. 动手前写下这一屏的两件事：用户要知道什么，要做什么。前者是标题，后者是主操作。
2. 其余的信息先试着用结构表达：分组和顺序表达关系，位置表达归属，图标表达类型和常见动作，灰度表达主次。
3. 结构表达不了的，才写成字。写成字的，再看能不能更短。
4. 写完逐行遮住小字：遮住后用户照样知道这是什么、该做什么，就删掉。

### 什么时候该写

说明只留给用户会犹豫或会后悔的地方，一句话，紧挨着对应的控件：

- **后果**：「关闭后，新笔记只保存在这台设备上。」
- **费用和额度**：「这次会用掉 3 次额度。」
- **不能撤销**：「删除后无法恢复。」
- **谁能看到**：「拿到链接的人都能查看。」
- **格式要求**：只在格式不明显时写，例如「至少 8 位」。

不写的：教用户怎么用界面的话（「在下方输入」「点击按钮即可」）、重复标题的话（标题「笔记」下面写「这里是你的笔记」）、欢迎语和口号、对功能的夸奖。

### 改前改后

| 不要 | 改成 |
| --- | --- |
| 标题上方小字「NOTES」，标题「你的笔记」，下方「在这里管理你的所有笔记」 | 标题「笔记」 |
| 输入框上方「在下方输入你的问题，按回车发送」 | 输入框加发送按钮，什么都不写 |
| 卡片：图标、标题、两行介绍、「AI」徽标、「了解更多 →」 | 标题，一行「3 天前 · 12 条」，整张卡片可点 |
| 「名称：设计周会」「时间：周三 14:00」「地点：3 楼」 | 「设计周会」，下面一行「周三 14:00 · 3 楼」 |
| 设置页每一项下面都有一句说明 | 只给会带来后果的那一项写 |
| 空状态：插画、标题、两段说明、三个按钮、帮助链接 | 标题、一句话、一个按钮 |
| 首页三张统计卡片「1,000+ 用户」「99.9% 可用」「24/7 支持」 | 没有真实数据就不放 |

### 限额

| 位置 | 最多 |
| --- | --- |
| 一个区块 | 一个标题；不加眉标（标题上方的小字分类），不加副标题 |
| 列表行、卡片 | 一行标题，一行灰色元信息（最多 3 项，用 ` · ` 分隔）；卡片标题说不清时才加摘要，最多 2 行 |
| 说明、页脚 | 一句 |
| 按钮 | 一个动词短语，中文通常 2 到 6 个字 |
| 徽标 | 只表达真实状态（草稿、已归档、3 条未读），一行最多一个 |
| 空状态 | 标题、一句话、最多两个按钮 |
| 首屏（官网） | 标题、一句话、最多两个按钮，见 [官网与文档](../scenes/web-marketing.md) |

### 图标代替字

- 搜索、关闭、更多、复制、发送、添加、设置、侧边栏开关这类常见动作，可以只放图标；必须有无障碍名称，有指针时用 [tooltip](../components/tooltip.md) 说出名称和快捷键。
- 其他动作用文字，或者图标加文字。用户需要停下来猜的图标，不如一个词。
- 文件类型、对象类型、状态可以用图标标出，省掉「类型：」这类标签。
- 不给每个标题、每张卡片、每个菜单项都配图标：一组里只有部分项有图标时，图标才起到区分作用。
- 必须让用户看到的信息（错误、限制、价格）不藏进 tooltip，直接写在界面上。

## 写法

- 用“你”称呼用户。语气平实直接，不用感叹号，不用 emoji。
- 关键词放前面：「删除 3 个文件」，不写「将选中的 3 个文件删除」。标题写具体的东西：「最近 7 天的用量」，不写「概览」「数据中心」。
- 标题是一个名字或一句话，不写成「笔记：记录你的灵感」这种两段式；标题、按钮、标签里不用破折号。
- 同一个东西只用一个名字：叫了「笔记」就不在别处叫「文档」「条目」。
- 不用套话：「智能」「一站式」「无缝」「赋能」「极致」「全新」「强大」。
- 按钮以动词开头，说清点了会发生什么：「保存」「新建笔记」「删除 3 个文件」。不用「确定」「OK」，也不用「了解更多」「立即体验」「开始使用」这类说不清去哪的字。操作完成后的提示用完成态：「已保存」「已复制」。
- 会再弹出一步（弹窗、选择）的菜单项和按钮，文字后加省略号：「重命名…」「导出为…」。进行中的状态也用省略号：「正在保存…」。直接执行的不加。
- 错误提示要说明出了什么问题、怎么解决：「网络连接已断开，恢复后会自动重试。」不道歉，不含糊。更多见 [反馈与通知](feedback.md) 的「错误怎么写」。
- 数量用阿拉伯数字：「3 个文件」，不写「三个文件」。中文与英文、中文与数字之间加一个半角空格：「同步到 iCloud」「剩余 12 次」。数字和单位用半角。
- 标题、按钮、标签不加句号；完整的句子加句号。
- 空状态写法：标题说明现在的状态，正文告诉用户下一步做什么。例如「还没有笔记」/「写下第一条想法，它会同步到你所有的设备。」
- 页脚和说明写清楚后果：「关闭 iCloud 同步后，新笔记只保存在这台设备上。」
- 示例和占位内容要像真的：用真实感的名字和内容，不用「张三」「测试 123」「Lorem ipsum」；不编造用户数、评价和客户名。还没有的内容标「示例」。
- 品牌名写作 Deernova。网站页眉、页脚这类品牌位置使用小写衬线的文字标识 `deernova.`（句点属于标识）；App 界面里写 Deernova 或具体的应用名。目前没有图形标志。
