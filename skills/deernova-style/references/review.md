# 审查清单

用来检查一个界面是否符合 Deernova。先确认它属于哪个场景（macOS、iOS、iPadOS、Web 应用、官网与文档），再按下面的顺序逐项看，只报告实际发现的问题。能量的地方实际去量，不要凭感觉。

## 检查项

- **场景与密度**：用的是这个场景对应的密度。应用界面没有用官网的尺寸，触屏上没有用桌面尺寸。Web 应用在触屏设备上切到了 `touch`。macOS 的系统控件保持系统尺寸，只有自己画的内容区用桌面 token。
- **控件高度**：实际测量默认按钮、输入框、列表行、顶栏、单行 Composer 的高度，等于对应 token（Web 应用桌面端是 28、28、32、44、44）。按钮的上下内边距是 0，文字行高是 1，高度不随页面行高变化。
- **点击区域**：可见尺寸小于 `hit-min` 的控件，有透明的命中区补足（Web 用 `::before`，SwiftUI 用 `.buttonStyle` 之后的 `.padding` 加 `.contentShape`）；没有为了凑点击区域把可见的控件做大。相邻控件的命中区不重叠。
- **层级与玻璃**：内容在不透明的纸面上。SwiftUI 端的侧边栏、工具栏、标签栏用系统玻璃，没有被实色背景盖掉；Web 应用里没有玻璃和模糊效果，操作层是不透明平面加 1px 线（官网页眉除外）。玻璃上没有段落和列表，没有玻璃叠玻璃；侧边栏比内容区亮一层。
- **颜色**：只有黑白灰；`accent` 跟随 `ink`，主按钮文字用 `on-accent`（深色主题下是黑字）；彩色只出现在状态上，并且同时有图标或文字；没有写死的十六进制颜色。
- **对比度**：实际测量前景和背景的组合，正文不低于 4.5:1，输入框边框等有意义的控件边界不低于 3:1。不要因为用了 token 就假定一定达标，要看它放在哪种纸面上。
- **线条与阴影**：分组靠 1px 线和间距；卡片没有阴影；阴影只出现在菜单、弹窗、浮动面板和 Composer 上；虚线只用在拖放区和占位块上。
- **字体**：界面文字和 AI 回答是无衬线；衬线只出现在大标题、空状态标题、官网和文章类长文；代码是等宽；字号来自角色变量（`--type-*`、`.deernovaX`）；iOS 用文本样式，没有写死字号；对齐的数字用等宽数字。
- **字重**：粗体只出现在真正的标题上；分组标题、会话名、顶栏标题、说明是常规字重，靠灰度区分。
- **间距与圆角**：间距在 4pt 网格上；组与组之间至少是组内的 2 倍；圆角来自组件的 `*-radius` token，嵌套圆角同心；阅读栏宽不超过 `content-max`。
- **交互**：一屏最多一个主按钮；按钮文字以动词开头；有悬停、按下、选中、禁用、加载、空、错误这些需要的状态；禁用和加载时布局不跳动；键盘焦点清楚；菜单和下拉点击才打开，Esc、点外面、选中一项都能关闭，焦点回到触发器，方向键能走完所有项；弹窗打开时背景不能操作也不滚动，关闭后焦点回到原处，危险确认默认聚焦「取消」。
- **动效**：时长来自 `duration-*`；动效说明因果；没有无目的的循环；减弱动态效果时只剩淡入淡出；切换内容时阅读位置不跳。
- **无障碍**：两套主题都看过；最大字号或 200% 缩放下不截断；只有图标的按钮有标签；降低透明度时玻璃变成实色。
- **文案**：用“你”；没有感叹号和 emoji；完成态用「已保存」；错误说明原因和解决办法；中文与英文、数字之间有半角空格。

## 怎么汇报

每个问题写清楚：严重程度（阻塞 / 明显 / 细节）、位置（文件和行号，或页面上的位置）、对用户的影响、具体怎么改（用哪个 token 或哪段参考写法）。把亲眼确认或实际测量过的问题，和推测的问题分开写。

审查不等于授权重做：只改被要求的范围，不顺手改动无关页面，也不提高项目的最低系统版本。
